# 阅读材料搜索的正文复用（2026-10-24）

本阶段从本地集成提交 `264d8ff31` 继续优化阅读材料列表的连续搜索。改动只在 `MaterialWorkspace`，没有改变仓库协议、存储格式、依赖、版本或权限，未使用参考仓库。

## 已测量的重复工作

原界面已在每次过滤前处理一次查询首尾空白和小写转换，空查询也已短路正文；本轮不把这些已有行为当成新增收益。非空查询仍为每份符合主题的材料重新拼接标题、来源 URL、主题以及所有引用的 excerpt/note，再执行默认 locale 小写转换。列表的前 30 项分页在过滤之后，不能减少这部分正文处理。

真实生产 SFC 的正式配对夹具使用 1,000 份合法材料、每份 8 条引用、每条 excerpt 300 字符。20 个不同查询会执行 20,000 次正文小写化，处理 49,515,600 个字符，excerpt/note 各读取 160,000 次。挂载和清空查询后的 30 行渲染均不读取引用正文；夹具提供独立定位引文，未选中详情，从而把正文 getter 计数与预览渲染分开。

## 有界复用与响应式失效

先按当前主题筛选材料，保留原顺序；被主题排除的材料不会为了建立索引而读取正文。非空搜索期间，私有 memo 保留已处理的小写字符串，额外文本预算为 4,194,304 个 UTF-16 code units，对应至多约 8 MiB 的 UTF-16 文本载荷，Map、对象与原始数据占用另计。

唯一字段收集函数维持原来的整体 `join(' ')`，不删除缺省字段形成的空格，也不拆成逐字段匹配。memo 在创建时调用该函数登记全部可搜索的深层响应式依赖，不拼接正文、不保留字段数组。过滤时只有缓存 miss 才拼接和小写化；放得下才写入 Map 并扣减预算，超预算材料当轮仍完整匹配，文本仅在当前循环中使用一次，后续小材料仍可以进入剩余缓存。

这项取舍使首次非空搜索多读一遍原字段来登记依赖，避免原地更新 note/excerpt、来源、主题或数组时命中旧文本。后续查询复用缓存；数据或主题变化会创建新的 memo。空或纯空白查询读取新的空缓存，旧 Map 不再持有小写正文和材料键；原列表、选中材料和未提交草稿仍由各自原有状态管理。未新增深层 watcher、定时器、全局缓存或后台索引。

纯 lazy computed 在清库后可能不再被空库模板读取，不能只靠下一次求值释放新增缓存。因此额外同步观察主题结果数组与搜索空/非空状态，列表、主题或空查询切换时直接清理既有 Map、将旧 memo 的 `items` 属性重赋为空数组并移除保留指针，卸载也走同一清理；不修改源数组，不读取新 memo，也不触发新的正文处理。验证捕获旧 memo 后执行清空、归档最后一项、空列表重载或卸载，直接断言旧 Map 不再含键、旧 `items` 不再持有材料，不通过读取新 computed 人为完成清理。这只证明新增 memo 的持有关系消除，不声称清理了已有 filtered/visible computed 列表的全部旧引用或测量了 GC。

## 交互与匹配边界

保持默认 `toLocaleLowerCase()` 和查询 `trim()`，不额外进行 Unicode 正规化。标题、URL、主题与全部引用正文之间的跨字段短语继续匹配，包括详情分页之外的引用。定位引文、来源标题、已解析问答或收藏译文、长期记忆正文及未保存草稿仍不进入搜索范围。

材料初始显示 30 项，继续显示每次增加 30；原始查询或主题变化仍重置数量，即使大小写或首尾空白归一化后相同。筛选不清理选中材料或草稿；没有匹配结果时原有布局隐藏行为保持，清空筛选后原选择仍可恢复。归档、恢复、导入、清空及同 ID 权威替换沿用原有客户端和异步所有权。

本阶段没有改变外层 KeepAlive 隐藏行为。已有 `active` 标志负责卸载和异步写入归属，不能为了停止隐藏刷新而直接改为显示状态；该候选需要单独验证实际父树与在途保存。

后续阶段已在此搜索实现上单独处理隐藏页的普通刷新，并保留已接受的保存、导入和导出。可见性与异步归属的设计及验证边界见[材料页隐藏刷新与操作归属](material-visibility-20261024.md)。

## 验证与证据

最终真实 SFC 消费者 42 项回归全部通过，其中包含原有 27 项和新增 15 项，覆盖连续输入的工作量、主题短路、完整匹配、深层更新、预算和首条超预算单次构造，以及原选择、草稿和分页行为。原匹配语义在不可变基线继续通过；新增缓存内部字段在原实现不存在，不能把相应断言失败称为原有产品缺陷。本轮中间候选的 Map 保留与 memo 材料列表保留分别由五个直接释放红例定位，并在最终源码通过；它们未被提交或发布。

同一 1,000 × 8 夹具的 20 次查询，正文小写化从 20,000 次降至 1,000 次；首次 excerpt/note 各读取 16,000 次，后续 19 次均为零。总引用字段读取各从 160,000 降至 16,000，但首次读取确实是原先 8,000 次的两倍。查询小写化仍为 20 次，查询 `trim` 从 20 增至 40 次，新增的一次用于搜索活跃布尔态。缓存实际文本为 2,475,780 字符，UTF-16 文本载荷为 4,951,560 字节，不含对象开销，也不是实际堆测量。

合法单份超预算夹具含 4,500,556 字符，仍能匹配末尾引用，每个查询只小写化一次且不写入缓存；随后 61 字符的小材料正常缓存。超预算部分仍需逐查询完整处理，本轮不声称消除这部分成本。

类型检查、Chrome/Firefox 构建、userscript 构建及 verifier、扩展 manifest 检查通过，源码头与验证归属 1,156 项通过。Chrome 未压缩产物为 516 个文件、62,999,986 字节，本阶段增加 468 字节；相对已核对的 `d580021e1` 主线仍净减 74,608 字节。userscript 维持 1,869,057 字节，权限与 CSP 不变。
