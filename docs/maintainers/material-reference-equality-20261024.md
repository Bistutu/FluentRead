# 阅读材料刷新时的引用比较（2026-10-24）

材料列表重载后，界面需要判断当前材料的学习引用是否变化，再决定是否使旧详情读取失效并补读。原实现对替换前后的完整 `references` 各执行一次 `JSON.stringify`，即使内容没有变化，也先构造两份包含全部原句和笔记的字符串。

本阶段将这个判断改为私有 `sameReferences` 比较，不增加缓存或长期保留的正文快照。范围限定为 `MaterialWorkspace` 的引用变化检测，沿用既有材料客户端、权威记录读取和可见性调度，没有借鉴参考仓库。

## 比较契约

比较全部引用，先检查数组身份、存在性和长度，再按原顺序检查当前 `MaterialReference` 的六个字段：`kind`、`id`、`excerpt`、`note`、`createdAt`、`updatedAt`。同一字段的缺省与显式 `undefined` 等价；对象键的插入顺序不参与语义比较。数组顺序、数量或任一字段不同都表示引用变化。

比较范围不能缩为当前可见的 24 条引用、只看 ID、只看更新时间或仅看正文长度。分页之外的引用变化仍沿原规则使详情读取失效。该函数是当前协议的字段比较，不是任意对象的通用深比较；将来扩展 `MaterialReference` 时，需要同步更新字段与实际消费者回归。

在 `reload` 中，旧引用数组在替换 `materials.value` 前保存，替换后立即读取新选择并比较，两步之间没有 `await`。当前相关的同步 watcher 只清理搜索 memo：清空 Map、将 memo 自有的 `items` 属性重赋为空数组，不修改源材料、旧引用数组或选择 ID。因此无须为了此处比较重新复制整份旧正文。若以后增加会同步改写旧引用的 watcher，需要重新审查这一前提。

## 详情与生命周期

检测到引用变化后，仍设置待详情读取、递增 `detailGeneration` 并释放旧读取等待；没有选中的材料则保持原有处理，材料已被删除时仍清理选择。需要读取详情时，继续通过原客户端取得收藏、问答或学习笔记的权威记录，这个比较不会缓存或代替那些记录。

引用内容未变化时，原 JSON 比较也不会仅因列表刷新而重读详情；本阶段保留该行为。手动详情重试、引用变化，以及隐藏期间被打断后恢复的补读仍由既有规则处理。不能把“引用相同”扩展解释为底层收藏或问答永远不变。

前阶段的隐藏调度保持：普通列表和详情读取可以在隐藏时合并，恢复且操作空闲后补读；旧显示代次的结果不能写回；已接受的保存、导入和导出继续完成。比较函数没有增加等待点，不更改错误归属、busy 收尾、草稿身份或焦点代次。相关设计见[阅读材料的可见性与延后刷新](material-visibility-20261024.md)。

## 计数层级与验证

正式配对运行相同真实 SFC 测试与客户端夹具，对照不可变 `7ae07d675` 和本阶段候选。选中材料、保留标题与笔记草稿，只更新 `lastReadAt`，连续刷新三次；原生 `JSON.stringify` 仍执行，只计数传入目标引用数组时生成的输出。

| 合法笔记引用夹具 | 三次刷新正文 JSON 次数 | 三次刷新正文 JSON 输出字符 |
| --- | ---: | ---: |
| 200 条，每条 excerpt/note 各 1,000 字符 | 6 → 0 | 2,503,746 → 0 |
| 1,000 条，每条 excerpt 6,000、note 12,000 字符 | 6 → 0 | 108,521,346 → 0 |

新路径去除的是用于比较的两份 JSON 输出。仍会读取并比较协议字段；字符串值比较、材料客户端读取、消息传输、Vue 依赖追踪及界面渲染的原有工作都存在。不能据该函数不再输出 JSON 宣称整个读取链零工作、零正文访问或已测量到某个堆占用降幅。
