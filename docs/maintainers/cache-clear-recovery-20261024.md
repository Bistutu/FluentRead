# 缓存清理等待与恢复（2026-10-24）

本次基于 `d580021e171f61f2efa986901c2c0ae273068435`，处理清除缓存后管理界面长时间停留在忙碌状态的问题，保存在独立分支 `codex/cache-clear-recovery-20261024`。未使用参考项目，也未更改权限、CSP、版本号或发布产物。

## 问题与行为

- Popup 原先没有等待截止。设置页虽然每条请求有 15 秒截止，清理后再读统计会重新获得完整预算，离开后也没有取消本地等待。
- 后台严格完成清库后，还会等待所有网页失效通知。一个页面消息不返回，就会拖住本来已经完成的清库回复。
- 设置页通过 `v-show` 与 KeepAlive 保留组件，单独处理卸载不能覆盖真实离页。高级选项内的锚点仍是同一连续表单，滚动定位不取消请求。

现在 Popup 和设置页共用可取消的消息等待：每次最多 15 秒，设置页的清理和随后统计共享同一个截止。关闭、隐藏所属分区、KeepAlive 失活或卸载会释放本地计时器和取消监听；返回时刷新统计并保留未保存的容量草稿。旧回复不能释放新请求的忙碌状态、更新结果或发起新的统计请求。全局翻译暂停仍允许清理缓存。

后台继续完整等待清库屏障、旧写入排空与持久存储清理，之后才开始 1 秒通知宽限。达到宽限时回复 `success: true, invalidationPending: true`，原通知继续运行，迟到拒绝保持被观察。正常及时完成仍保留原来的明确成功响应。这里没有给存储屏障增加超时，也没有因界面取消而取消后台清理。

界面区分三种结果，并补齐七种语言：

| 情况 | 反馈 |
| --- | --- |
| 后台已确认清理、通知及时结束 | 原有清理成功提示 |
| 后台已确认清理、页面通知尚未确认 | 后台缓存已清除，部分页面仍在同步 |
| 15 秒内未拿到清理确认 | 暂未确认清除结果，请稍后刷新 |

清理已确认后，统计超时会单独提示读取用量失败，保留已清理状态。
