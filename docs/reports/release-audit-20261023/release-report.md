## 性能与体积

| 项目 | 实测结果 | 边界 |
| --- | --- | --- |
| 文档内联标记，2,048 ID | 遍历项 4,200,448→8,192；144.85→8.45 ms | 本地模块，2 次预热、7 次中位数，输出相同 |
| 1,000 条个人校订候选 | 查询分词 1,000→1 次；32.62→15.94 ms | 9 组×5 次，仍只返回五个建议 |
| 64 个传统/免费失败正文样本 | 读取 67,108,864→0 字节；clone 64→0 | 本地 64 个 1 MiB 流，不代表线上提速比例 |
| PDF 纯布局，18 真实页 | 75.00→49.52 ms，约减少 34% | 5 次预热、15 轮交替，修复版输出 SHA256 相同 |
| OCR 竖排分组 | 2,048 行减少 2,096,128 个候选元素复制 | 时间差未达到显著水平，不宣称浏览器峰值内存改善 |
| 22 个 PNG/JPEG | 原始资源减少 19,197 字节；同 deflate-6 减少 4,348 | 解码 RGBA、ICC 相同 |
| 同一原基线文件 ZIP，level 6→9 | 36,022,785→35,887,947 字节，减少 134,838 | 525 文件解压哈希相同；单次打包 2.70→4.62 秒 |
| S8 同 527 文件 ZIP，level 6→9 | 36,024,047→35,889,225 字节，减少 134,822（0.3743%） | 两控制与正式包解压 CRC/SHA 相同；并行验收下单次 6.02→10.51 秒，仅为打包成本 |
| S8 正式 Chrome ZIP 对原基线 | 相对旧 level6 减少 133,560；相对旧 level9 增加 1,278 字节 | 当前功能与资源均有变化，不能把整体差异归功于图片优化 |
| 五份 standalone 静态 gzip 的 Base85 表示 | 字面量减少 51,653 字节 | 解码后 gzip 与正文哈希一致；未压缩可执行代码，整包 gzip 略增，不声称压缩下载更小 |
| S8 普通 userscript | 1,857,226 字节，通过原 2,125,100 上限 | HTTP 端口协议对照及真实构建接线通过，保留协议来源许可 |
| S8 standalone | 3,592,912 字节，通过原 3,600,000 上限 | 没有远程 @require，所有离线功能与资源保留 |
| S8 Greasy Fork | 2,916,980 字节，未通过原 2,000,000 上限 | 保持可读产品源码，不改 minify、不降低门槛 |

OpenAI 兼容层仍按锁定 SDK 合同消费错误正文；上述避免读取的收益不覆盖所有供应商。普通脚本共享 HTTP 与原 SDK 的 payload、端点、请求头、重试、租约、预算和用量；执行器不运行宿主页注入的 SDK telemetry 钩子，项目没有自有消费者依赖该钩子。491 项接线/协议/供应商定向测试及独立 190 项合同通过。完整脚本保留库与协议许可。Base85 仅改变五份已有非代码 gzip 的字节表示，Node 本地解码基准明显降低耗时，不能推导真实浏览器启动收益。

GM 阅读存储 35 项四维 100%；永久墓碑仍随删除次数增长。新笔记仅复制当前 ID、相同内容及全清的适用标记，避免每次保存复制全部历史删除。GM 没有跨标签事务，不能承诺线性一致性；并发最后名额可能各自先返回成功，最终列表按确定性投影不超过 200。

删除未用图片构建依赖及其 2,184 行锁文件，其他依赖版本保持原锁定。Greasy Fork 的纯字面量全部外置也不足填补当前缺口；没有为体积删除核心功能。原始基线 GF 构建在生成产物前已因既有资源提交与锁文件不一致失败，不能据此认定基线也超过 2 MB。
