# 连续滚动阅读等待优化（2026-10-11）

基础提交：`c8a06bb5fe0148f629ecaf60e70e5bf6ebb4f957`。任务分支：`codex/reading-wait-priority-20261011`。改动针对全文翻译在连续滚动中等不到空闲窗口的等待；悬浮翻译只做回归验证。本次没有借鉴或修改参考仓库。

## 原因与实现

原调度器要求滚动安静 220ms 才派发全文候选。每 80ms 继续滚动时，这个窗口不断后移；当前段落已进入可见区域，也会等到手势结束后才请求服务。候选排序、视口范围、方向预取、后台公平配额和跨功能请求调度已经存在，无需重建。

复用现有 `flushTimer`，滚动期间每 120ms 最多开始三个真正可见的候选；后续滚动事件不重置已安排的计时器。先过滤可见候选再运行既有优先级计划，避免超龄后台公平配额阻挡当前阅读段落。滚动事件也唤醒 drain，覆盖候选从 IntersectionObserver 的 rootMargin 区域进入真实视口但没有第二次交叉回调的情况。空闲后继续既有预取与公平调度。

三个是单轮候选上限，仍受原配置并发、8ms 时间片和共享请求限速约束。已有在途请求不被抢占，正文候选可以合成一个 HTTP 请求；独立标题翻译仍按原路径执行。候选完成后沿用原渲染和会话归属检查，恢复、关闭和导航仍撤销计时器、队列与请求。没有添加状态层、渐进展示或重译修复结构。

真实浏览器还复现了一个既有重试问题：失败 UI 稳定 500ms 后点击重试，旧控件先移除 wrapper；MutationObserver 将该移除视为宿主撤回失败 UI，撤销刚排入的重试，3 秒内没有新的正文 HTTP 请求。现在 boolean 回调由 runtime 保留反馈，实际开始新一代翻译时才清理；接受或拒绝排队时都保留可见反馈。旧 void 回调继续执行原清理语义。

## 测量方法

- 浏览器：Edge `131.0.2903.147`；外窗 1280 × 900，实际内容视口 1272 × 816 CSS px、DPR 2（两版截图均为 2544 × 1632 像素）。使用生产 Chrome MV3 扩展。基线是独立目录构建的上述基础提交，新版是本任务生产构建。
- `launchMode=macos-background-cdp`、`focusPolicy=launchservices-no-foreground`、`windowPlacement.mode=background-visible-no-focus`，正常窗口位于第二屏，`browserFrontmost=false`。每次使用临时 profile，结束后关闭自有浏览器并清理 profile。
- 同一 HTML 材料 SHA-256：`6ea993c691ce0b2da10676f2c7f9a00c0a44c6a96dfde3afb98e5fe2084275c8`。80 段、每段最小高度 210px；目标为首屏 p0–p2 和跳转后 p40–p42。1000 段整页模式另测 p900–p902。
- 同一设置：微软协议、英译中、双语、缓存和自动翻译关闭、候选并发 3，配置的每秒/每分钟限速为 0，AI 上下文和多段合并关闭。供应商 fetch 被导向本机 HTTP，固定延迟 180ms；非本机 HTTP 禁止。请求实际经过生产 client、后台、协议和 DOM 渲染。
- 首屏用真实 Alt+T；随后跳转到新段落，20 次每隔 80ms 前进 3px，持续至少 1600ms。三个阅读锚点始终可见。首次可读要求 RAF 观察到当帧任一可见段落的译文 wrapper 自身边界与视口相交，屏外已挂载译文不计入。视口完成为当帧全部可见段落都出现一份译文 DOM，部分可见也计入；计时包含触发和调度。单纯 DOM 首次就绪、指定三段和初始视口快照的完成时间另记，避免混淆口径。
- 跳转与起点记录在同次 evaluate 中完成。初始只扫描一次可见集合，再监测其前后各两个邻段（本夹具最多九段）；每帧读这些段落的实际边界，避免对 1000 段逐帧扫描。终点另做一次全页可见扫描并断言没有漏掉屏内段落。本次慢滚总位移 60px、段落最小高度 210px，这个有界监测适用于该材料。
- 80 段首屏与滚动各重复三次，报告中位数和各轮请求数；1000 段整页模式单次。计数固定观察首屏 800ms、滚动 2600ms，包含窗口内所有实际 HTTP 及文本槽，而非只计目标段落。`PerformanceObserver` 记录至少 50ms 的主线程长任务。

连续滚动首次屏内译文中位数减少约 83.8%，视口 DOM 完成中位数减少约 71.4%；新版均在约 1630ms 的滚动结束前完成。所有 case 的首次屏内译文与首次 DOM 就绪时间本次一致，但两项独立记录并实际检查译文 wrapper 边界。

首屏变化较小，不据此宣称首屏提速。80 段滚动 HTTP 中位数从 4 增至 5（增加一个请求），文本槽中位数均为 11；相同文字工作可能因合批时序产生更多请求。1000 段单次窗口内 HTTP 为 5→8，文本槽 12→14，新版空闲后更早继续工作，多处理两个槽。本次优化有请求成本，不能称为零额外工作或零额外 HTTP。

两版所有测量均未观察到至少 50ms 的长任务，只能描述该夹具的本次结果。三轮对比和单次大页面是小样本，不用于推导总体用户收益。

首屏实际可见集合为 p0–p3，80 段滚动为 p39–p43，1000 段为 p899–p903；起点与终点集合一致。视口完成是这些屏内候选的译文 DOM 就绪，不要求部分可见段落的整份译文都挤在一屏内。以后继续滚到新段落仍可能等待后续翻译。

## 生命周期与验证

完整新版生产扩展专项通过九项行为断言：

- 三个在途正文槽占满时，连续滚动不新增正文派发；全程最大正文一槽候选并发为 3。最终完整运行的 HTTP 峰值为 3；既有独立标题允许另占一个 HTTP。
- 在途恢复拒绝迟到结果，重新翻译后恢复无重复或残留；全局关闭撤销在途正文 HTTP 且不提交旧 DOM。
- 恢复旧会话后切换目标语言，再调用采用新语言，迟到旧语言结果不进入页面。
- 动态可见段落只生成一份译文并可恢复；失败点击发出新的正文 HTTP，随后只保留一份译文并可恢复。
- 导航后替换文档不接收旧结果；悬浮 Control 翻译—恢复—再翻译的译文数为 `[1, 0, 1]`，邻段保持 0。

最终浏览器报告的页面异常、console error、非本机网络和清理异常均为空；自有浏览器与临时 profile 均已清理。基线重试专项复现预期失败，修复后的限定重试专项及完整流程都通过。

## 证据边界

这些数字证明固定 180ms 本地传输下的插件等待和 DOM 就绪，不能推导在线供应商延迟、译文质量、任意网站、低端设备或真实用户滚动的同等收益。首次可读不是整个文档完成；标题 HTTP、正文候选与文本槽是不同单位。本次已有在途请求占满时，当前段落仍等待原槽释放。

目标语言切换验收先恢复旧会话再改变配置并重新调用；既有会话保留冻结配置。Firefox 和 userscript 构建通过不等于对应浏览器实机验收。1000 段单次长任务观察不能证明所有大页面没有长任务，首屏数值也不用于宣称普遍提速。
