## 实现与成本

内容页持有两个网站名单的 `Set` 索引。路由查询不再反复归一化整份名单，禁用和自动翻译复用同一次当前地址的基础域解析。同值的新数组保留索引；名单原地修改、添加、删除、留空位后填回都会更新索引。只缓存最近一个地址的基础域，缓存不随浏览历史增长。域名规则仍沿用现有 tldts 解析、private suffix、IDN、IP 和非法网址边界。

配置通知仍逐项比较名单内容，成本是 O(N)，真实修改会重建变化的那个名单。首次构造会提前解析两份名单，即便全局自动翻译已打开或扩展暂时关闭；默认空名单不做域名解析。查询变快的同时，初始化和真实编辑承担索引成本，不能将这项优化描述为所有场景都更快。

生命周期协调改为共享一个在途任务。同一轮同步通知只处理一次；挂载等待期间再收到通知，完成后再读取一次最新状态。关闭扩展仍同步释放功能和在途翻译，路由取消也继续立即执行。挂载失效重试上限保持两次，批次异常后允许后续独立请求恢复。

Popup 网站规则保存移除调用方多余的一次完整 `normalizeConfig`，由原有配置存储完成同步快照、归一化、差量提交和确认。仍捕获同一轮其他设置草稿，不减少持久化校验、不绕过后台确认。测试使用实际 store 验证标量及嵌套草稿、保存后立即修改旧嵌套引用、在途新编辑和旧确认不覆盖新值。没有把配置预处理微测当作点击到保存完成的延迟。

## 工作量与测量边界

纯 Node 对照覆盖 0 / 10 / 100 / 1,000 条每名单、命中位置、未命中、重复地址、锚点、原地修改、同值通知、全局标志和混合路线。计时使用未包装的模块；另编译包装模块统计 `getDomain` / `parse` 次数，包装仍调用同一真实 tldts，不替换域名语义。轮次交替运行新旧实现，保留全部样本；低于 0.2ms 的批次不计算速度比例。受控查询每次评估禁用与自动翻译两个判断，不代表精确浏览器事件轨迹。

两个名单各 1,000 条时，索引预热后的 10 次未命中或新锚点地址查询，域名解析从 30,030 次变为 10 次；10 次完全相同地址查询从 30,030 次变为 0 次。同值及仅标志变化的更新不重新解析名单；修改一份名单的一项仍解析该名单的 1,000 项。这些是确定的模块工作量，不包含浏览器 DOM、渲染、翻译服务和网络耗时。

最终 dd070 模块对照完成 48 个场景、1,586 次语义比较及 22 步累计修改校验。Node 24.19.0 / M1 Pro / 同一 tldts 7.4.10 与锁文件；测量采用显式共享 3 槽、maxWorkers 1，实际使用 lock-1，内部串行七轮，并未独占 CPU。两个名单各 1,000 条的混合工作负载（同值通知、五个地址查询和真实编辑），10 轮批次中位数为 207.95 → 10.24ms。首次 20 次构造中位数 41.38ms，约 2.07ms/次；同值新数组 500 次更新仍有线性比较成本。计时是同步批次的经过时间，包含 OS 调度，不能解释为精确 on-CPU 时间或实际网页加速比例；解析次数是主证据。源文件散列、全部计时样本、低于下限的不计算比例及初始化/更新成本均保留在 [performance.json](./performance.json)。

生命周期对照直接加载新旧模块，以注入的挂载器和规则判断统计调用：

| 场景 | 旧版本 | 新版本 |
| --- | --- | --- |
| 同一轮 100 次通知：挂载器调用 | 100 | 1 |
| 同一轮 100 次通知：bridge 同步 / 映射 DOM 事件 | 200 / 400 | 2 / 4 |
| 挂载在途再来 100 次通知：挂载器调用 | 101 | 2 |
| 挂载在途再来 100 次通知：bridge 同步 / 映射 DOM 事件 | 202 / 404 | 4 / 8 |
| 两种场景：实际启动挂载 / 自动翻译 | 均为 1 / 1 | 均为 1 / 1 |

调用数来自确定性 fixture；DOM 事件数按 composition root 每次 bridge 同步发送两个事件映射，不是浏览器时间采样。禁用同步、完成微任务窗口内重新启用、失败恢复和两次重试上限另有测试断言。

## 定向验证

性能原始阶段涉及 9 个测试文件，1,478 个不同用例通过；覆盖率复跑不重复计数。集成最新主线后，同样 9 个文件复验，6 个功能文件 523 项与 3 个静态/构建配置文件 958 项，共 1,481 项通过。包括网站规则 25、内容 composition root 46、生命周期 19、Popup 37、全文可见性调度 339、Popup 操作归属 57、userscript 构建配置 32、源码文件头 913、模块边界 13。网站规则与页面可用性模块的 statements / branches / functions / lines 重新采集后仍均为 100%。覆盖率配置排除了静态/构建配置文件，因此这三个文件通过普通 Vitest 单独执行，未将命令参数当作已执行证据。测试分类审计通过，652 个文件、10,908 个用例仅做分类，不是全量测试通过声明。

Chrome、Firefox 和 userscript 均构建成功，两个扩展清单及 userscript verifier 通过。Firefox / userscript 仅验证构建与相应产物边界，未做真实运行时验收。集成主线前类型检查仅有已知 `MangaModelSettings.vue(35,7): TS6133 props is declared but its value is never read`；最新主线已移除此未使用变量，最终集成类型检查成功。该无关修复来自主线，不计为本任务交付。

性能原始阶段 userscript 为 2,026,422 bytes，相对上一轮正确产物增加 528 bytes（0.0261%）；此前的 2,026,000 预算不足，按实测最小提高 1KB。最终集成产物为 2,026,916 bytes，在 2,027,000 预算内，余量 84 bytes。这个最终体积也包含新主线的变化，不能把与旧产物的总差额归因于性能优化。语言资源重新生成并固定到包含合并后五个语言 JSON 的 `57b76a06a54d8849c5de2f7a239a4cf3cb3b014e`。各阶段体积、失败与最终通过、散列及比较见 [userscript-size.json](./userscript-size.json)。

最新主线 c8a06bb5f 在独立 archive 中使用同一锁文件、依赖构建为 2,024,873 bytes，原 verifier 通过。4,949 个 tracked 源文件在六个检查点逐字节保持一致；语言生成未新增文件，仅生成缺失的七个 WXT 文件和构建产物。最终 PR 全部正确性、交互与性能变更比该主线增加 2,043 bytes（0.1009%），这也不是性能单项增量。
