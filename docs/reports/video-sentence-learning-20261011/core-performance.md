# 完整句学习核心性能对照

基线提交为 `4791ac7f3c718543615d2f58d7c4ec2fa0707e0c`，候选为执行时工作树中的 `sentenceTimeline.ts` 和 `sentencePlayback.ts`。测量时候选源码尚未提交，因此不能仅凭记录中的候选 `HEAD` 识别被测代码；[原始 JSON](performance/core.json) 保存两个版本逐文件的 SHA-256、字节数、Node/CPU/编译器版本、全部样本与测量参数。

## 复跑

在该 Git 工作树根目录、已安装项目依赖的环境中运行：

```sh
node scripts/testing/run-resource-safe.mjs -- node scripts/testing/benchmark-video-sentence-learning.cjs \
  --baseline 4791ac7f3c718543615d2f58d7c4ec2fa0707e0c \
  --output docs/reports/video-sentence-learning-20261011/performance/core.json
```

[仓库脚本](../../../scripts/testing/benchmark-video-sentence-learning.cjs) 通过 `git show` 读取基线两份 TypeScript 源码，通过 Vite 的依赖解析位置取得现有 esbuild，在系统临时目录编译并加载两个版本，结束时清理临时目录。脚本不依赖某个 `/tmp` 路径，不复制旧源码到仓库，不修改生产源码或构建产物。输出路径可另选，以保留本次记录。

## 工作负载与等价检查

- 普通和长重叠时间轴各包含 120、2,400、12,000 句，每种使用相同的 10,000 次确定性乱序时钟查询。基线调用原 `findVideoSentenceAtTime` 后 `indexOf`；候选调用一次构建的 `findIndexAtTime`。测量前逐项验证全部 60,000 次查询结果相等。
- 普通 cue 间隔 1,000ms、持续 800ms，包含空隙；长重叠模式每 29 个 cue 加入覆盖长时间范围的原始 cue，验证查询不能只看最近开始的短句。
- 聚合工作负载为 12,000 个无标点中英文 cue，先检查两个版本完整输出深度相等，再测量聚合耗时；最终均生成 897 个材料段。
- 空闲控制器使用 Node `EventTarget`，每轮派发 100,000 次 `timeupdate`，分别模拟仍连接和已断开的媒体，验证最终控制状态均为关闭。它不播放媒体，不测量循环或句末暂停精度。

每项预热 3 轮、测量 7 轮，比较两个版本时交替先后顺序，报告中位数。索引首次构建耗时和预热后的构建中位数独立记录，不计入查句耗时。

## 本次结果

实际仓库入口执行一次并通过全部等价检查。环境为 Node `v20.11.1`、macOS arm64、Apple M1 Pro；esbuild `0.21.5`，目标 `node20`，未压缩。

| 句数 | 模式 | 基线 10,000 次查询 ms | 候选 10,000 次查询 ms | 首次构建 ms | 构建中位 ms |
| ---: | --- | ---: | ---: | ---: | ---: |
| 120 | 普通 | 2.006 | 0.545 | 0.182 | 0.016 |
| 120 | 长重叠 | 1.985 | 0.647 | 0.022 | 0.015 |
| 2,400 | 普通 | 36.188 | 1.941 | 0.307 | 0.113 |
| 2,400 | 长重叠 | 38.984 | 1.915 | 0.150 | 0.140 |
| 12,000 | 普通 | 181.908 | 2.145 | 1.734 | 0.544 |
| 12,000 | 长重叠 | 217.375 | 2.067 | 0.378 | 0.313 |

聚合中位数为 22.946 → 22.286ms，变化较小。空闲事件的派发中位数接近：断开媒体 3.226 → 3.097ms，连接媒体 4.115 → 4.069ms，因此不据此主张整体速度明显提高。

空闲操作计数更明确：每个媒体连接状态的 10 轮累计 1,000,000 次事件，`isConnected` 读取从 1,000,000 次降为 0；断开媒体的重复状态通知从 1,000,000 次降为 0。JSON 的 `stateChangesIncludingDestroy` 还包括最后一次 `destroy()` 通知，因此对应原值为 1,000,001 → 1。

## 解释边界

这些数字只证明当前机器上纯时间轴索引减少了重复扫描，以及未选句时避免了无用的媒体读取和状态通知。网络请求、Vue 渲染、真实媒体事件调度、字幕捕获和用户操作体验应以另行记录的真实浏览器证据评估；不能把上述查询倍数称为完整句学习的端到端提升。

此前临时 harness 使用 TypeScript 转译，本报告使用仓库入口的 esbuild 编译与交替测量，保留的是此次实际运行的全部样本。跨运行、跨机器的绝对耗时会波动，应从同一进程内的对照及结果等价性判断。
