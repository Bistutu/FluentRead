# 完整句学习性能与操作验收

2026-10-11。基线对应提交 `4791ac7f3` 的 Chrome 生产产物，测试前复制到独立临时目录，避免后续构建覆盖。生产内容脚本 SHA-256、浏览器模式、窗口位置、每次测量、请求数、页面异常和清理结果保留于 [基线 JSON](./baseline-browser.json)。两个平台共八个针对性场景通过，无 pageerror、浏览器激活 0，browser/profile 均清理成功。之前已通过的 74 项功能验收与原站空字幕证据保持独立。

## 测量方法

沿用 `fluentread-browser-translation-test` 的独立临时 profile、第二屏正常后台 Edge 窗口和原生焦点观察，不连接日常浏览器、不激活前台。真实本地 MP4 为 960×540、20fps、18 秒；字幕是受控原始时间轴，微软传输固定延迟 120ms。字幕显示设为原文，避免原字幕覆盖层的翻译请求混入学习请求；两个平台使用不同文本，避免跨平台缓存混入请求计数。

长时间轴分别为 YouTube 120/2400/12000 句、X 120/2400/4000 句。X 当前 sidecar 管线最多保留 4000 条字幕，没有放宽生产守卫。该压力时间轴每个 cue 为 1ms，整个范围位于真实媒体时长内；媒体暂停并实际 seek 到首句或尾句，每处派发十批、每批 100 个模拟 `timeupdate`，记录同步事件分发总时间。它是密集输入的模拟压力，不能代表用户视频会产生每秒 1000 个事件。关闭面板时的同样分发作为全页基础成本对照。

操作场景使用 120 条 500ms 间隔原字幕，以可信 CDP 按钮输入切到第 12 句，每次点击后等待 30ms；实际点击间隔包含 CDP 开销，原始时间戳见 JSON。同步 12 次合成点击的微任务结算另列，不能当作真人手势延迟。按钮事件到句子 DOM 提交采用页面内 `performance.now()` 与 MutationObserver；不包括输入自动等待、下一帧绘制或供应商耗时。已完成草稿重访使用同一面板会话。

真实时钟场景另开干净页面，只观察 6 秒首句中的 5 秒自然播放，不用密集 12000 句压力材料冒充正常视频。DOM 变化分别统计整页和学习卡自身；字幕覆盖层的既有更新不会归到学习卡。关闭测试先绑定循环、重播，再关闭面板，确认真实时钟能跨越旧区间。

## 基线结果

| 场景 | YouTube | X |
| --- | ---: | ---: |
| 最大时间轴首部 / 尾部，1000 次模拟事件 | 47.1 / 48.8 ms（12000句） | 200.2 / 192.4 ms（4000句） |
| 相同页面关闭面板，1000 次模拟事件 | 18.3 ms | 174.3 ms |
| 快速切 12 句的传输次数 | 10 | 10 |
| 快切按钮事件→DOM p50 / p95 | 1.1 / 2.3 ms | 1.0 / 2.4 ms |
| 同步 12 次点击 burst 的传输次数 | 1 | 1 |
| 已完成草稿来回重访的新增请求 | 0 | 0 |
| 自然首句播放 5 秒 | 19 次原生 tick；学习卡 DOM 0；新增请求 0；longtask 0 | 19 次原生 tick；学习卡 DOM 0；新增请求 0；longtask 0 |
| 关闭后跨越旧循环结束点 | 媒体正常越过 6 秒，面板 0，请求 0 | 媒体正常越过 6 秒，面板 0，请求 0 |

打开原始 120 句操作面板的事件→DOM 为 YouTube 19.1ms、X 18.6ms；最大时间轴分别为 37.6ms 和 26.3ms。这是每个场景一次观测，不能作为稳定分位数。模拟事件总时间包括原有字幕运行时：X 即使关闭学习卡仍有较高事件分发与全页 DOM 成本。学习卡自身在同句压力下的 DOM 变化和新增请求均为 0，因此不能把整页的 3000/27000 余次变化描述成学习卡反复渲染。

390×260 播放器在完整原文位置能直接点重播、收藏、学习中心和关闭；上下句及播放辅助需要滚动正文后才能点击。已有键盘操作和正文滚动使它们可达，但频繁换句需要额外滚动。实图见 [YouTube 基线小播放器](./youtube-compact-before.png) 和 [X 基线小播放器](./x-compact-before.png)。

## 优化后同协议观察

优化产物来自 `/private/tmp/video-learning-perf-chrome.log` 的 Chrome 成功构建（34.2 秒），内容脚本 SHA-256 与逐场景记录见 [优化 JSON](./optimized-browser.json)。相同八个性能场景通过，无 pageerror、前台激活 0，browser/profile 均清理成功。

| 相同场景 | 基线 | 优化后 |
| --- | ---: | ---: |
| YouTube 12000句首部 / 尾部，1000次模拟事件 | 47.1 / 48.8 ms | 23.3 / 23.4 ms |
| YouTube 同页关闭面板分发对照 | 18.3 ms | 18.4 ms |
| X 4000句首部 / 尾部，1000次模拟事件 | 200.2 / 192.4 ms | 205.8 / 185.7 ms |
| X 同页关闭面板分发对照 | 174.3 ms | 186.0 ms |
| 快切12句传输次数（YouTube / X） | 10 / 10 | 1 / 1 |
| 快切按钮→DOM p50（YouTube / X） | 1.1 / 1.0 ms | 0.4 / 0.4 ms |
| 快切按钮→DOM p95（YouTube / X） | 2.3 / 2.4 ms | 1.0 / 1.3 ms |
| 同步12次点击传输次数（YouTube / X） | 1 / 1 | 1 / 1 |
| 已译草稿重访的新增请求 | 两平台均0 | 两平台均0 |

YouTube 大时间轴在该批模拟压力下的同步分发耗时下降；X 的全页基础成本与批间噪声较高，这批没有证明 X 的稳定整体提速。自然首句的 5 秒真实时钟在优化前后均为两平台各 19 次原生 tick、学习卡 DOM 0、新增请求 0、longtask 0，关闭后均能正常越过旧 6 秒边界。120句操作面板打开一次的 YouTube / X 观察为 19.1 / 18.6ms→18.6 / 19.9ms；12000句 YouTube 为 37.6→36.3ms，没有把这些单次观测宣称为稳定打开速度改善。

请求合并保留即时句子 DOM 更新，仅对主动换句等待 120ms，首次进入和自然跟随仍直接发起。小播放器头部新增固定的上一句/下一句，优化 JSON 的原文视口中心命中证明两者可直接点击；正文中的播放辅助仍需滚动或使用 R/Q 快捷键。切句会将阅读正文滚动归顶；折叠取消未启动的换句计时器，隐藏时不自动启动新请求，展开补当前空译文。已确认且未修改的收藏按钮禁止重复保存，编辑后仍可更新。

## 最终功能与操作验收

相同 Chrome 产物另跑功能专项，原有 74 项保留，两平台各增加三项操作断言，共 80 项、十个场景全部通过；无 pageerror、浏览器激活 0，browser/profile 清理成功。[最终功能 JSON](./functional-browser.json) 与性能 JSON 分开，旧 74 项报告及图库仍保留当时产物的历史事实。

- 快速可信切句与同步合成 burst 都保留最后选择的原句、时间和译文，分别只启动最终句一次传输。
- 换句后立即收起取消未启动计时器；隐藏期间键盘换句不启动自动请求，展开只补当前句一次，关闭也释放待发请求。
- 390×260 播放器的固定上一句/下一句/重播/关闭按钮可实际中心命中；滚动后的主动换句将正文归顶，完整原句可见，R/Q/方向键仍控制对应区间且不隐式播放。

原有主动收藏检查同步改为等待“已收藏”禁用，并核对完整持久化记录没有变化；空译文、清空讲解、编辑后更新和同区间来源仍走原有断言。没有为新截图增加额外收藏数据，默认阅读态的已收藏按钮保持浅粉文字与背景。实图见 [普通阅读态](./youtube-learning-after.png) 和 [小播放器固定换句与收藏](./x-compact-after.png)，两图均已目视检查。这里只验收390×260尺寸，没有据此保证任意更小高度的布局。

最终功能原始材料保留于 `/private/tmp/fluentread-video-sentence-learning-performance-ux-final-20261011`。首轮新操作夹具切换显示模式时，完整保存公开配置漏掉独立存储的测试占位凭据，导致后续 X 讲解报缺少 API Key；已仅在 runner 保留本批已知占位值后重跑全部80项，没有读取用户凭据或改动生产配置机制。

## 复跑与边界

使用现有专项 runner 的显式 `--performance-only --performance-tag <产物标记>`，同时传入 `--extension-dir`、`--playwright-root`、`--focus-safe-helper`、`--platforms youtube,x` 和独立 `--artifacts-dir`。性能模式独立于默认功能专项，不运行原站探测。原始最终基线保留在 `/private/tmp/fluentread-video-sentence-performance-baseline-final-20261011`。

两次前期协议排查分别发现 X 夹具超出既有 4000 条上限，以及同 profile 缓存/X sidecar 合并旧材料的混杂；这些结果没有列为优化基线，也没有认定为产品回归。此后固定平台独立文本、自然时钟独立页面和有界 X 数量。

以上只证明所列生产 UI 与数据处理行为。没有追加真实站点或真实提供商测试，原站原字幕供应后的完整闭环仍未验收；Firefox 运行时、画中画、低端设备、长期会话和供应商质量没有被这些数值覆盖。基线与优化结果采用同一协议分列，没有覆盖基线。
