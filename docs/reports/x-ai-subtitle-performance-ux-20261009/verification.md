# X 本地字幕性能与交互验证

日期：2026-10-09。基于 `8467b6757affb4bc895d44fa8fbf12a65bee7479`，继续修复本地字幕性能和交互；默认逐窗自动检测语言，不要求用户预先知道视频语言。

## 改动与原因

- 自动语言检测与转写复用当前音频窗的特征，避免重复计算 Mel 特征。只在锁定的 Transformers.js 3.8.1、完整单窗和匹配的处理器契约下复用；不兼容时沿用原流水线。请求结束恢复实例属性，释放当前特征和编码张量，失败重试不继承上一窗。
- 停止或卸载时取消隐藏扫描播放器的元数据等待，清理事件、计时器和节点。此前这些资源可能继续等待原有 2500 ms 超时；不会暂停或移除网站拥有的播放器。
- 播放器的字幕选项显示当前识别模型，可打开 Tiny/Base/Small 选择。确认前保留当前字幕，取消或 Escape 返回可见操作焦点；确认后才保存选择并重新识别。生成中的预览不能导出为完整字幕。模型名称与下载状态分行显示，长语言标签不会相互挤压。
- 导出反馈计时器统一交还当前菜单状态，防止先前导出结束后的旧回调重新启用新一轮识别中的按钮；卸载同时取消原文、译文和双语的反馈计时器。
- 模型可用状态核对实际 Cache Storage 文件清单，设置与播放器共用后台状态。缺文件时重新提供补下载入口，复用已有文件；缓存读取失败单独报错。Tiny/Base 接受完整 q4 或完整 q8，不能混用两份不完整清单；Small 仍使用 FP32 encoder 与 q4 decoder。检查只读 Request 元数据，不读取权重响应体、不加载模型、不删除登记。
- 播放器下载进度通过受信后台查询传递，避免网页内容脚本被本地存储访问限制挡住。查询只返回合法下载标识的归一化字节数，下载期间每 500 ms 串行查询；停止订阅屏蔽迟到结果，并设 600 秒上限。新下载忽略旧会话残留进度，换视频、停用功能或卸载立即停止查询；后台已确认的下载继续完成。设置页继续使用现有存储事件。

菜单请求从历史大文件抽出到 `content/video-ai/modelMenu.ts`；没有提高原架构体积上限、增加权限、升级依赖或修改参考仓库。

## 下载进度通道反例

V4 生产产物的实际菜单验收中，Small 下载始终显示不确定状态。单独诊断对精确进度键写入受控 25%、75% 字节数并删除：受信后台收到三次变化，受信扩展页面可读取对应值，网页内容脚本没有收到任何变化，两次直接读取均被浏览器拒绝。原因是既有配置存储保护将 `storage.local` 限为 `TRUSTED_CONTEXTS`，而此前播放器只监听该区域的变化事件。

该[诊断证据](./progress-channel-baseline.json)证明真实权限与通信缺陷，不代表实际模型下载速度；未运行模型或识别 Worker。首次诊断自动化误用可见性等待的失败另行保留，不计产品结果。

## 缓存缺陷基线

使用不可变 PR #903 生产扩展，缓存与后台源码与当前基线对应。专用临时 Chrome 154 中流式写入实际 Small 七文件，共 588,744,805 字节，各文件核对 SHA 与大小。完整时真实后台和设置均显示可用；只删必需的 `tokenizer.json` 后，实际剩六个键，但后台仍返回 `models: ['small']`，设置仍显示“可离线使用”。这直接证明下载登记不能代表当前文件完整性。

该运行没有远程请求、识别 Worker、ONNX 或转写。原始反例报告保留在本机 `/private/tmp/fluentread-video-model-cache-state-proof-20261009/baseline-retry-1/report.json`。基线截图捕获锚点滚动过程，不能作为模型卡片状态的视觉证明；状态结论来自真实后台与卡片 DOM。第一次导航自动化失败单独保留，不计产品通过或失败。

候选生产扩展在相同七文件缓存中重复删除 tokenizer，真实后台返回 `models: []`、Small 不可用，设置显示“尚未下载”和“下载模型”。点击真实设置下载入口后，生产缓存准备流程仅补齐缺失的 2,480,466 字节 tokenizer，SHA 为 `27fc476bfe7f17299480be2273fc0608e4d5a99aba2ab5dec5374b4482d1a566`；缓存恢复七文件，后台与设置重新显示可用。已有两个 ONNX 文件没有再次传输，也没有创建识别 Worker。

补下载使用受控传输：只在该临时 profile 的 offscreen target 将 tokenizer 请求导向已登记的本地 HTTP 服务，DevTools 阻止所有 HTTPS，并记录实际请求与服务传输。真实后台消息、下载准备、缓存写入与设置按钮保持生产路径。它证明缺文件识别与补齐行为，不证明公共模型站连接或下载速度。此前普通页面拦截无法观察 offscreen 请求的一次运行保留为失败证据，不把未观察到请求记为零网络。最终缓存报告位于 `/private/tmp/fluentread-video-model-cache-state-proof-20261009/candidate-final-v3-offscreen/report.json`，临时浏览器已安全关闭并删除 profile；[精简证据](./cache-integrity.json)保留状态、传输、模型 SHA 与自动化边界。该产物与最终 V6 的模型缓存、视频后台及设置源码完全一致，V6 另外修复导出销毁保护和下载进度通道。

## 真实模型对照

实际生产 Worker 在单线程 WASM 上执行 Base 自然英文 JFK 与 Small FLEURS 印地语样本。音频经生产 PCM16 解码，自动语言检测、生成参数、模型精度和时间戳处理保持一致；只适配 Node 消息宿主与本地模型/WASM 加载边界，禁用网络。

| 固定样本 | 特征计算次数 | encoder 次数 | 特征计算耗时 ms | 总推理耗时 ms |
| --- | --- | --- | --- | --- |
| Base / JFK | 2 → 1 | 1 → 1 | 255.87 → 121.86 | 5623.38 → 5480.38 |
| Small / hi_in_0000 | 2 → 1 | 1 → 1 | 266.16 → 126.37 | 37750.40 → 38161.19 |

两组文字、时间戳、检测语言和置信度的结果摘要严格相同，decoder 次数分别保持 31 与 114。每窗避免一次特征计算是确定收益；这是每模型一次顺序对照，Small 总耗时反而略增，不能据此宣称整体识别加速、准确率提高或浏览器/GPU 性能改善。

最终源码另外执行两次候选调用，与固定旧版结果摘要相同。特征计算耗时分别为 120.66 ms 和 128.73 ms，总推理为 5445.95 ms 和 37708.76 ms；这一补验不覆盖或替代上表波动记录。原始顺序对照的[精简指标](./processor-reuse-paired.json)与[最终源码摘要](./processor-reuse-final.json)保留输入、源码、模型文件及结果 SHA，没有提交音频、权重或完整转写。
