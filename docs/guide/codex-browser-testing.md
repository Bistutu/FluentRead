# 浏览器自动化测试

这份页面面向维护者，记录如何在真实浏览器中验证 FluentRead 0.0.29 的段落翻译生命周期。它不是普通用户的安装教程；普通用户请从[安装与第一次翻译](/guide/getting-started)开始。

## 测试目标

对一个包含多个普通段落的页面执行：

1. 只翻译鼠标所在的目标段落；
2. 恢复目标段落原文；
3. 再次翻译目标段落；
4. 确认相邻段落没有被影响，也没有重复插入译文。

## 推荐手势

使用浏览器自动化时，按键名称必须使用标准的 `Control` 或 `Meta`，不要使用自定义的 `CTRL` 字符串。一个稳定的段落翻译手势是：

```text
移动到目标段落的普通文字
→ 单击普通文字
→ 发送一次 Control/Meta 按键
→ 等待翻译结果或失败状态
```

不要点击段落中的链接，也不要在请求仍未结束时连续触发快捷键。

## DOM 断言

翻译成功后，目标段落应出现 FluentRead 自己的内容节点，例如：

```css
.fluent-read-bilingual-content
```

恢复原文后，该节点应被移除。第三次操作后，目标段落只能保留一份译文节点；相邻段落不应新增节点。

## 最小检查表

- [ ] 使用真实浏览器加载当前生产构建，而不是只测试 Vue 组件。
- [ ] 目标段落完成“翻译 → 恢复 → 再翻译”。
- [ ] 相邻段落保持原状。
- [ ] 没有重复的 `.fluent-read-bilingual-content`。
- [ ] 没有意外跳转、全文翻译或控制台未处理异常。
- [ ] 测试截图和 DOM 快照中不包含 API Key、Cookie 或个人信息。

## 本地开发建议

使用隔离的浏览器 profile 加载 `.output/chrome-mv3-dev`，不要把开发构建注入正在使用的个人浏览器。服务配置和测试页面也应使用专门的、可撤销的凭据。
