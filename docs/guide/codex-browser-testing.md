# 用 Codex 操作浏览器翻译插件：指定段落翻译与状态切换测试

本文记录如何让 Codex 操作 Chrome 中的“流畅阅读”插件，对网页中的指定段落进行翻译，并验证“翻译—恢复—再次翻译”的切换效果。

## 插件配置

测试时采用以下配置：

- 插件状态：开启
- 翻译模式：双语对照模式
- 译文样式：加粗显示
- 翻译服务：硅基流动
- 目标语言：中文
- 鼠标悬浮快捷键：`Ctrl`
- 全文翻译快捷键：`Alt+T` 或 `Option+T`
- 模型：自定义模型

其中，指定段落翻译依赖“鼠标悬浮快捷键”，不需要启动全文翻译。

## 指定段落的操作方法

正确的操作顺序如下：

1. 将鼠标移动到需要翻译的段落上。
2. 在段落的普通文本区域单击一次，使浏览器确认当前操作目标。
3. 单击并立即松开 `Ctrl` 键。
4. 等待译文生成。

这里的 `Ctrl` 是一次普通按键，不需要持续按住。

如果段落中包含链接，建议点击普通文字部分，避免点击链接后跳转到其他页面。

## 翻译结果

插件会在原文下方追加中文译文，形成双语对照：

```text
As described in RFC 2606 and RFC 6761, a number of domains...

正如 RFC 2606 和 RFC 6761 所述，一些域名……
```

在实际测试中，插件只处理鼠标所在的第一段，第二段仍然保持英文。这说明指定段落翻译不会误触发全文翻译。

## 恢复原文

如果当前段落已经包含译文，再执行一次相同操作：

1. 鼠标移动到已经翻译的段落。
2. 单击段落中的普通文本。
3. 单击并松开 `Ctrl`。

插件会移除该段落下方的中文译文，页面恢复为纯英文。

## 再次翻译

恢复原文后，再执行一次相同操作，中文译文会重新生成。

完整的三次切换应为：

1. 第一次：生成中文译文。
2. 第二次：移除译文，恢复原文。
3. 第三次：重新生成中文译文。

三次操作均应成功，而且最终只保留一份译文，不应出现重复插入。

## Codex 自动操作时的注意事项

在自动化测试中，按键名称必须使用标准的 `Control` 事件。

使用 `CTRL` 时，浏览器虽然可能执行按键动作，但插件无法识别，因此不会触发翻译。改为标准 `Control` 后，指定段落翻译才能生效。

完整的自动化手势可以概括为：

```text
鼠标移动到段落
→ 单击普通文本
→ 发送一次 Control 按键
→ 等待翻译结果
```

判断操作是否成功，可以检查目标段落中是否出现：

```html
<span class="fluent-read-bilingual-content">
```

恢复原文后，该元素应被移除。

测试时还应确认：

- 目标段落以外的相邻段落没有新增译文。
- 划选段落中的部分文本后触发快捷键，只翻译选区。
- 对超长语义段落或以空行分隔的视觉段落触发快捷键时，应完整翻译该段；只有缺少段落结构的大型文本容器才按句群分块。
- 第三次操作后，目标段落中只有一个 `.fluent-read-bilingual-content` 元素。
- 操作没有触发链接跳转或全文翻译。
- 翻译请求仍在进行时，应等待结果或明确的失败状态，不要连续重复发送快捷键。

## 测试结论检查表

- 可以只翻译鼠标所在的段落。
- 再次按下快捷键可以恢复原文。
- 支持反复切换翻译状态。
- 不会影响相邻段落。
- 不会重复插入译文。
- 双语排版清晰，译文加粗后容易区分。

对于只想临时查看某一段中文含义、又不希望整页被翻译的场景，这种交互方式比较实用。
